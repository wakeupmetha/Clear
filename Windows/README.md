# Windows-версия

Два проекта. `Core` — логика без интерфейса и без движка, перенесённая из `Sources/Search/` почти дословно. `App` — окно на WinUI 3 и WebView2 поверх неё, в дизайне версии для macOS.

Стек: C#, .NET 10, Windows App SDK 2.7. Ядро собирается без пакетов и без сети; окну нужны пакеты с nuget.org, источник задан в `nuget.config` этой папки.

## Запустить и проверить

Нужен .NET 10 SDK. Visual Studio не нужна.

```powershell
dotnet run --project Windows/App
```

```powershell
dotnet run --project Windows/Tests
```

Запуск из папки сборки всегда идёт в тестовом мире: данные лежат в `%LOCALAPPDATA%\aerio (test)`, настоящих он не касается. Проверки ядра возвращают код 1, если хоть одна не прошла.

## Установщик

```powershell
Windows/pack.ps1
```

Скрипт публикует релизную сборку (со своим .NET и Windows App SDK внутри) в `Windows/dist/app` и упаковывает её Velopack в `Windows/dist/Releases`. Версия — `<Version>` в `App/App.csproj`. Папка `dist` в git не идёт.

- `aerio-browser-win-Setup.exe` — установщик. Ставит для текущего пользователя, прав администратора не просит: программа в `%LOCALAPPDATA%\aerio-browser`, ярлыки `aerio` на рабочем столе и в «Пуске», запись в «Установленных приложениях» для удаления. Если на машине нет движка WebView2 (бывает на Windows 10), установщик поставит его сам.
- `aerio-browser-win-Portable.zip` — то же без установки: распаковать и запустить `aerio.exe`.
- Данные человека (вкладки, история, настройки, входы) лежат отдельно, в `%LOCALAPPDATA%\aerio`, и удаление программы их не трогает. Поэтому имя пакета `aerio-browser`, а не `aerio`: Velopack при удалении стирает свою папку целиком.

Инструмент `vpk` — локальный инструмент .NET (`dotnet-tools.json` в этой папке, ставится командой `dotnet tool restore`); его версия совпадает с версией пакета `Velopack` в `App.csproj`. Первая строка `Program.Main` (`App.xaml.cs`) отдаёт слово Velopack: установщик запускает программу со служебными ключами, и она должна выйти, не показав окна.

Размер. В пакет не кладутся части Windows App SDK, которыми браузер не пользуется (`pack.ps1`, `--exclude`): родные библиотеки ИИ, поиска и виджетов — `onnxruntime.dll` и `DirectML.dll` (40 МБ), `Microsoft.Windows.AI.*`, `Microsoft.Windows.Search`, `SemanticIndex`, `Widgets`, `Graphics.Imaging` — а ещё чтение pdb и переводы встроенных элементов WinUI (86 языковых папок, 3,4 МБ; надписи окна и так на английском). Управляемые обёртки к этим библиотекам остаются: они записаны в `aerio.deps.json`, и без них программа не запустится.

| | Setup.exe | Portable.zip | Папка программы | Файлов |
|---|---|---|---|---|
| 0.1.12, всё подряд | 108,4 МБ | 101,2 МБ | 259 МБ | 1192 |
| без ИИ и переводов (задача 13) | 83,1 МБ | 75,9 МБ | 199 МБ | 1008 |

Облегчённую сборку проверили упакованной в тихом окне: служебный запуск установщика, окно, страница, история, настройки, печать, приватные вкладки, закладки, загрузки, расширения — 0 провалов. Память и время запуска те же: 107 / 383 / 577 МБ, окно — 414 мс, первая страница — 415 мс. Дальше без смены набора пакетов не уменьшить: самое крупное, что осталось, — `Microsoft.Windows.SDK.NET.dll` (24 МБ, обёртки Windows SDK для .NET), сам .NET и WinUI. Их режет только обрезка (`PublishTrimmed`) или общий пакет Windows App SDK вместо своего — это решение владельца.

Чего в установщике нет:

- **Подписи кода.** Windows при запуске установщика покажет предупреждение SmartScreen («Подробнее» → «Выполнить в любом случае»). Нужен сертификат — решение владельца.
- **Обновлений с сервера.** Выпуски негде размещать. Новая версия ставится новым установщиком поверх старой: поднять `<Version>` в `App.csproj`, `pack.ps1`, запустить `Setup.exe` (проверено 0.1.0 → 0.1.1: старый пакет заменяется, ярлыки и данные остаются, браузер открывается сам). Перед установкой браузер надо закрыть — штатно, чтобы он записал вкладки. Или изнутри — см. ниже.
- **Сборки для ARM64.**

### Обновление изнутри

Settings → Updates → «Update aerio» (`App/Updater.cs`, решение владельца: «Пересборка здесь»). Кнопка собирает aerio заново из исходников на этом компьютере — `pack.ps1 -Bump`: последняя цифра `<Version>` в `App.csproj` поднимается на одну, файл меняется только в версии — и ставит собранное поверх себя (`UpdateManager` Velopack, источник — `dist\Releases`). Затем окно закрывается штатно (вкладки и история записаны), установщик ставит новую версию и запускает её. Пока идёт сборка, на кнопке «Building…», под описанием — что происходит; ошибка сборки или установки — там же красным, с последними строками сборки.

Откуда собирать, программа знает из своей сборки: `App.csproj` кладёт в неё путь к папке `Windows/` (метаданные `Source`). Если этой папки с `pack.ps1` на компьютере нет — кнопки нет, в описании «The source isn't on this computer». Обновляется только поставленная установщиком программа или переносная из `Portable.zip`; в сборке из `bin` кнопки нет («Only the installed aerio updates itself»). Пакет с этим путём внутри — для себя: для выпуска наружу собирать с `-p:SourceFolder=none`. `git pull` перед сборкой не делается: собирается то, что лежит в папке.

Проверено на переносной копии в тихом окне (`check-update.ps1`, 7 из 7; установленная программа не тронута): «Update» есть в копии 0.1.7, фокус во время сборки остаётся на кнопке, через 25 с окно закрылось и копия запустилась заново уже 0.1.8 (версия в `App.csproj` поднята), на той же вкладке настроек и в том же тестовом мире; перед этим проверено, что программа, которую запускает Velopack, получает окружение тестового мира.

`dotnet publish` без `EnableMsixTooling` в проекте не кладёт в итог `aerio.pri`, и такая программа падает при запуске, хотя сборка в `bin` работает. Поэтому после упаковки проверяется именно упакованное: распаковать `Portable.zip` и запустить `current\aerio.exe` в тихом окне.

Окно открывается там, где его закрыли, и того же размера: при закрытии рамка обычного (не развёрнутого) окна пишется в `window.frame` (`x,y,ширина,высота` в точках экрана), развёрнутость — в `window.zoomed`. При запуске рамка ставится на экран, где больше всего полосы окна, ужимается до его рабочей области и сдвигается внутрь целиком; полосы нет ни на одном экране (его отключили) или рамка испорчена — 1280 на 840, куда поставит система (`Core/WindowFrame.cs`, 10 проверок). Развёрнутым окно открывается развёрнутым, кроме тихого: развёртывание делает окно активным. В апстриме главное окно восстанавливает macOS. Проверено в тихом окне (`check-frame.ps1`, 8 из 8; окно двигалось `SetWindowPos` без активации): рамка записана при закрытии, второй запуск там же, рамка за экранами и испорченная — как в первый раз, больше экрана — ужата до рабочей области. Развёрнутость в тихом окне не проверена.

Вкладка, на которую давно не смотрели, засыпает, как в апстриме (`Sleep.swift`): отдаёт движок — его процессы и память, — а адрес и заголовок оставляет; перейдёшь на неё — проснётся и загрузит страницу заново. Ждёт полчаса (Normal), два часа (Later) или десять минут (Sooner); выбор — Settings › Tabs › «Sleep tabs you aren't using», там же Never. Не спят: вкладка перед глазами, загружающаяся, со звуком, с идущей загрузкой файла и с набранным, но не отправленным текстом (поле или редактируемый блок с текстом; не ответила за 3 с — тоже не спит). Смотрим раз в четверть ожидания, от 5 с до минуты, дольше всех оставленные — первыми. Отличия от апстрима: просыпается загрузкой адреса — без истории «назад», места прокрутки и картинки на время загрузки (`ponytail:` в `Tabs.cs`); при нехватке памяти ожидание не сокращается; затемнения спящих нет. Проверено в тихом окне (`check-sleep.ps1`, 9 из 9; с `sleep.after` = 3 с: две оставленные вкладки уснули, процессов движка 10 → 8).

Первый переход движка повторяется один раз, если он оборвался (`ConnectionAborted`) до первой страницы. В свежем профиле с только что поставленным uBlock Chromium обрывает первый заход на Chrome Web Store, и без повтора вкладка оставалась пустой. Так же обрывается переход, который стал загрузкой, а `DownloadStarting` приходит уже после конца перехода. Поэтому вторая загрузка после повтора отменяется: это та же самая. Отменяется именно вторая по счёту, а не загрузка с тем же адресом: у подписанных ссылок на файл адрес меняется от запроса к запросу. Проверено в тихом окне (`check19.ps1`, 5 из 5). Свежий мир открывает магазин. Быстрый и медленный файл в новой вкладке скачиваются по одному разу, вкладка остаётся пустой.

Ссылки извне, как `Links.swift` апстрима: `aerio.exe <адрес>` открывает адрес вкладкой. Берутся http, https и страницы на диске (.html, .htm, .xhtml); ключи, путь программы, pdf и mailto пропускаются (`Address.Launched`, `Address.Words`, 3 проверки). Пустая вкладка перед глазами берёт адрес сама. Окно на мир одно (`AppInstance` Windows App SDK, ключ — папка мира): второй запуск отдаёт свои адреса уже открытому окну, выводит его вперёд и выходит. Без адресов второй запуск только выводит окно вперёд и разворачивает свёрнутое. Раньше второй запуск открывал второе окно на тех же вкладках и той же папке движка. Браузером по умолчанию aerio себя не записывает: это меняет настройки Windows, решение владельца. Проверено в тихом окне (`check30.ps1`, 7 из 7): запуск с адресом, второй запуск с адресом и страницей с диска (выходит за ~130 мс), запуск без адресов, окно другого мира, вкладки после перезапуска. Вывод окна вперёд в тихом окне выключен.

Интерфейс собран в коде, без XAML: единственный `App.xaml` подключает стили стандартных элементов. Каждый цвет — одна кисть на всё приложение, смена темы переписывает её цвет.

Что есть: вкладки в колонке, страница карточкой, поле адреса (Ctrl+L, Ctrl+T, нажатие на живую вкладку), подсказки из истории, значки сайтов, светлая и тёмная тема вслед за системой, восстановление сессии без запуска движков, история, блокировщик рекламы, складывание колонки, тонкая полоса прокрутки, служебные страницы движка, страница настроек, страница истории.

Окно проверяется скриптом `drive.ps1`: он запускает тихое окно в своём тестовом мире, шлёт команды в тест-канал и снимает только это окно.

## История

История — своя страница во вкладке с адресом `browser://history`. Открывается строкой History внизу колонки, по Ctrl+H или набранным адресом; в окне она одна, движок для неё не запускается.

На странице: поле поиска (по заголовку и адресу, подстрокой), под ним дни («Today», «Yesterday», дальше дата), у каждого дня карточка мест. Нажатие на место открывает его в новой вкладке. Под указателем вместо времени появляется «Remove». Значок и заголовок строки стоят под значком и подсказкой поля поиска. Подвал идёт сразу за списком (при длинном списке список прокручивается, подвал виден) и занимает одну строку: слева сколько мест, справа «Clear…». У пустого списка («Nothing yet.») счётчика нет. «Clear…» открывает вместо этой строки карточку «Clear browsing data» с «Done» в заголовке и тремя строками, у каждой справа одинаковая «Clear» (для диктора — «Clear history», «Sign out of everything», «Clear cache»). «History» стирает всю историю и закрывает карточку. «Cookies and sign-ins» стирает куки и хранилища сайтов (выход отовсюду). «Cache» стирает кэш движка. После двух последних карточка остаётся открытой; «Done» её закрывает, фокус после открытия — на «Done», чтобы второй Enter ничего не стёр. Стереть историю одним нажатием нельзя. Куки и кэш стираются у профиля движка, общего для всех вкладок; если ни одна вкладка не проснулась, на время очистки поднимается невидимый движок (`Tabs.Sweep`). Открытые страницы узнают о стёртых куках при следующей загрузке. Об окончании очистки страница не сообщает.

Несколько мест можно выбрать: Ctrl+щелчок (или Ctrl+Enter на строке) выбирает место или снимает выбор, Shift+щелчок добавляет все места от прошлого выбранного до этого, Ctrl+A в списке выбирает все места в виду, Esc снимает выбор. У выбранной строки галочка вместо значка и подсвеченный фон. Подвал тогда показывает «N selected», «Deselect» и «Remove»; «Remove» и Delete на любой строке убирают все выбранные. Выбор держится только за места в виду: поиск, скрывший место, снимает с него выбор.

С клавиатуры список — одна остановка Tab: между строками ходят стрелками, Enter открывает место, Delete убирает его (или выбранные), и фокус остаётся на строке, вставшей на его место. Экранному диктору видны и строка, и её кнопка «Remove».

Строки списка создаются только для того, что в виду: из 2200 мест в дереве окна около 23 строк, страница открывается за 23 мс. Память оболочки при этом выросла со 157 до 173 МБ (сборка Debug).

Отличия от апстрима. Место открывается в новой вкладке, а история остаётся открытой: там оно открывается в той же вкладке, и «назад» возвращает к истории, а здесь у своей страницы нет движка и «назад». Пальцем строку не убрать: у касания нет наведения.

В историю попадает заголовок только загрузившейся страницы: страница ошибки движка («127.0.0.1», «localhost») заголовок места не переписывает (`Tab.Landed`).

## Закладки

Как в апстриме (`Bookmarks.swift`), базово. Список — `bookmarks.json` (`Core/Bookmarks.cs`) с ключами апстрима: файл с Mac читается как есть, с папками. Кнопка-закладка в полосе, после Reload, залита на сохранённой странице; щелчок сохраняет страницу или убирает закладку. На пустой вкладке и своей странице кнопка недоступна. Ctrl+Shift+B («Add This Page», ⇧⌘B апстрима) только добавляет: сохранённая страница так и остаётся. Новая закладка встаёт в конец списка с заголовком страницы, а без заголовка — с адресом. Та же страница второй раз не сохраняется.

Страница `browser://bookmarks` открывается строкой «Bookmarks» внизу колонки, между History и Settings. На ней поле поиска (все слова, в любом порядке и регистре, в имени или адресе — правило `matches` апстрима) и карточки: первой — сайты верхнего уровня, под ней по карточке на папку с её путём («Work › Deep»). У строки значок сайта, имя и адрес. Щелчок открывает сайт в новой вкладке, как в истории; крестик или Delete на строке убирают закладку.

Проверено в тихом окне (20 проверок, 0 провалов): кнопка и её имя для диктора, недоступность на своей странице, Ctrl+Shift+B из страницы (через отладочный протокол), поиск, открытие, удаление, файл с Mac с папками, перезапуск.

Отличия от апстрима: щелчок по кнопке сохраняет и убирает, а не открывает список под кнопкой. Карточки закладки (имя, папка) нет, поэтому закладку не переименовать, папку не завести и закладку не перенести; папки из файла с Mac только показываются. Панели закладок, импорта из других браузеров и закладок в подсказках адресной строки тоже нет.

## Значки сайтов

У строки вкладки, подсказки в поле адреса и строки истории — значок сайта, а пока его нет — первая буква сайта на бледной плитке. Значок открытой страницы отдаёт движок: тот, что объявила сама страница, или её `/favicon.ico`. Для сайта, который есть в истории, но значка которого на диске нет, браузер сам просит `/favicon.ico` у этого сайта, не открывая страницу (решение владельца): без куки и входов, не больше одного раза за сеанс, не больше четырёх запросов сразу, не дольше 8 секунд. Чужого сервиса значков нет: никто, кроме самого сайта, не узнаёт, что набрано.

У своих страниц вместо значка сайта — значок Lucide: часы у истории, шестерёнка у настроек, колба у `edge://flags` (`Mark.Sign`).

Значок один на сайт (хост без «www.» и порт, если он не по умолчанию) и лежит файлом в папке `icons` хранилища, поэтому после перезапуска и у спящих вкладок он сразу на месте. Принимаются только PNG, ICO, JPEG, GIF, BMP и WebP, от 60 байт до 1 МБ; больше 4000 файлов — самые старые стираются. Clear history стирает и значки; запрос, начатый до неё, значок после неё не кладёт.

Отличия от апстрима. Там значок у каждой страницы и есть тёмный вариант; здесь один на сайт. Значок, объявленный страницей, для неоткрытого сайта не ищется: разбирать HTML ради него пока незачем. Сайт, за значком которого уже ходили, после Clear history получает значок только от движка, при открытии страницы.

## Настройки

Настройки — своя страница во вкладке с адресом `browser://settings`, как `chrome://settings`: её можно оставить открытой, вернуться по Ctrl+Tab, закрыть по Ctrl+W. Открывается строкой Settings внизу колонки, по Ctrl+запятая или набранным адресом. В окне она одна: второй раз идём к уже открытой. Движок для неё не запускается. Сайт открыть её не может, ни ссылкой, ни новым окном.

Страница разбита на разделы, как в апстриме (`Settings.swift`): слева рельс, справа один раздел. Разделы в трёх блоках, как там: Appearance (группы Light and dark, Window), Tabs (Memory) и Browsing (Searching); Passwords (Your passwords, Filling in forms), Privacy (Blocking, Site Permissions, Cookies and Site Data), Extensions (Installed) и Keyboard (Shortcuts); About (Updates, Developer). General и Spaces & Pins апстрима появятся со своими первыми строками. Открытый раздел помнится в `settings.page` (ключ апстрима), незнакомый ключ — первый раздел. Разделы — радиокнопки с именем для диктора, фокус берут с клавиатуры. Проверено в тихом окне (`check-sections.ps1`, 16 из 16).

У каждой строки настроек свой значок Lucide (Appearance — солнце и луна, Search with — поиск по тексту, блокировщик — щит, uBlock Origin — ползунки, движок — процессор, расширения — папка и магазин). Подписи в капсулах и в переключателе темы стоят посередине капсулы: строка текста обрезана по буквам (`TextLineBounds.Tight`), снизу у капсулы поле на 2 точки больше — так Segoe UI выглядит посередине (замер по снимку: в пределах 0,5 точки).

Что настраивается:

| Настройка | Ключ в `settings.json` |
|---|---|
| Светлое окно, тёмное или как в Windows | `look` |
| Сложить колонку вкладок | `sidebar.folded` |
| Режим фокуса | `window.focus` |
| Поисковик и адрес своего поисковика | `search.engine`, `search.custom` |
| Блокировщик рекламы | `shield` |
| Сайты, на которых блокировщик выключен | `shield.paused` |
| Защита от отслеживания (выключена, если `true`) | `sites.keep` |
| Предлагать сохранить пароль | `passwords.save` |
| Заполнять формы | `contacts.fill` |
| Открытый раздел настроек | `settings.page` |
| Сон вкладок и как скоро (`later`, `normal`, `sooner`) | `tabs.sleep`, `tabs.sleep.pace` |
| Секунды до сна вместо выбранного — для проверок и замеров | `sleep.after` |

Ещё на странице есть кнопка, открывающая `edge://flags`. Ключи и значения те же, что в апстриме.

Защита от отслеживания, пароли и формы — настройки самого движка через его API, а не флагами (решение владельца 2026-11-21). Их применяет `Tabs.Dress` к профилю каждого проснувшегося движка и `Tabs.Redress` — ко всем живым, когда настройку сменили. «Prevent cross-site tracking» (Privacy) включена — уровень движка `Balanced`, как в Edge; выключена — `None`. Группа «Passwords and Forms»: «Offer to save passwords» (`IsPasswordAutosaveEnabled`; по умолчанию включено, как в апстриме, хотя у движка выключено), «Fill in forms» (`IsGeneralAutofillEnabled`: имена, адреса, почта, телефон; по умолчанию включено — в апстриме выключено только потому, что macOS спрашивает про Контакты), «Forget All» стирает сохранённые пароли и записи форм всех сайтов (`ClearBrowsingDataAsync`), со второго нажатия: первое переспрашивает на 4 с. Отличие от апстрима: списка сохранённых паролей нет — движок его не отдаёт (`ponytail:`). Проверено в тихом окне (`check-engineprefs.ps1`, 12 из 12): умолчания профиля, переключатели меняют профиль сразу, после перезапуска движок снова их получает, «Forget All» переспрашивает и стирает без ошибки.

Разрешения и данные сайтов — своими разделами, а не страницами движка (просьба владельца: «стилизованные меню cookie и прочих инструментов в настройки»):

- «Site Permissions» (`privacy.forget` апстрима): все сайты, которым движок что-то разрешил или запретил, с тем, что именно («Camera: Allow · Location: Refuse»; кроме четырёх из карточки сайта — и остальное, что движок помнит: буфер обмена, загрузки, шрифты…). Крестик у сайта забывает его выбор (`SetPermissionStateAsync` с `Default`), «Forget All» — выбор всех сайтов;
- «Cookies and Site Data»: сайты с куки и сколько их; куки поддоменов собраны в сайт (`Address.Site`: две последние части имени, у `co.uk` и похожих — три; `ponytail:` без списка публичных суффиксов). Крестик стирает куки сайта и хранилища его источников (`Storage.clearDataForOrigin`): хостов из его куки, самого сайта и www по https и http, и источников из истории — только там известен порт. «Clear All» («Sign out of everything») стирает куки и данные всех сайтов, как в карточке очистки истории. Больше восьми сайтов — над списком поиск; показываются первые 30 (`ponytail:`). Сайт, у которого нет куки, а есть только хранилище, в списке не виден.

Списки читаются из движка при открытии настроек; если ни одна страница не проснулась, на это время поднимается невидимый движок (`Tabs.WithEngine`). Проверено в тихом окне (`check-sitedata.ps1`, 12 из 12): разрешение из карточки сайта в списке, «забыть» стирает в движке и разрешение, и отказ; после перезапуска со спящими страницами списки на месте; крестик стирает куки (и на другом пути) и localStorage одного сайта, у другого всё цело; «Clear All» стирает всё.

Страница — только вид на настройки. Элементы пишут в `Settings`, а окно, вкладки и сама страница узнают о смене из `Settings.Changed`. Поэтому настройка действует сразу, без перезапуска, откуда бы её ни сменили: Ctrl+S двигает и переключатель на открытой странице.

Отличия от апстрима. Поиска по настройкам нет: разделов восемь, строк в них немного (`ponytail:` — появится, когда строк станет столько, что раздел не найти глазом). Сайт, на котором блокировщик выключен, набирают в списке, и запись действует на его поддомены; в апстриме сайт выключают из карточки вкладки и записывают её хост как есть.

Переключатели, выбор темы и кнопки страницы сделаны из стандартных элементов Windows с нашим рисунком: они берут фокус с клавиатуры и названы для экранного диктора.

## Адресная строка

В полосе окна, посередине над страницей — тихая строка (`App/Bar.cs`, просьба владельца): значок сайта и заголовок страницы. Под указателем вместо заголовка — серым адрес страницы, как его покажет поле (просьба владельца: «ссылку не показывать по умолчанию, а только при наведении»), и плашка темнеет; строка при этом не двигается и не меняет ширину. Нажатие открывает поле адреса, как Ctrl+L. На пустой вкладке — значок поиска и «Search or enter address»; у своих страниц (настройки, история) сайта в имени для диктора нет; когда заголовка нет и в нём уже адрес, сайт второй раз не называется. Строка шириной 560 точек, как всплывающее поле, а где места меньше — ужимается (Grid по месту между кнопками полосы с `MaxWidth`); значок и текст — слева, длинные заголовок и адрес обрезаются многоточием, целиком он — в имени для диктора («заголовок, сайт. Edit address»). Строка не заходит под кнопки слева, когда колонка сложена, и под кнопки окна справа; место под ней забрано у перетаскивания окна, как у кнопок полосы, и пересчитывается после каждой раскладки (складывание колонки, размер окна). В апстриме такой строки нет — поле всплывает. Вид — поле, как в Helium (просьба владельца 2026-11-21: строка шириной по тексту прыгала под указателем — без указателя 177 пикселей, под ним 587 и левый край на 205 левее; а в узком окне заходила на кнопку uBlock): плашка видна и без указателя. Проверено `check-barwidth.ps1` (3 из 3): ширина и место строки под указателем те же (560), адрес обрезан многоточием, в окне шириной 760 строка ужата до 140 и не заходит на кнопки справа. Проверено в тихом окне (`check-bar.ps1`, 10 из 10): подсказка, сайт, адрес под указателем и заголовок после (указатель — командой `hover`), своя страница, длинный заголовок, нажатие открывает поле, места полосы со сложенной и развёрнутой колонкой; снимки тёмной и светлой темы. Настоящей мышью строку в тихом окне не нажимали (указатель человека): места полосы сверены через тест-канал.

## Карточка сайта

Слева от адресной строки на странице сайта (http и https; у своих страниц и пустой вкладки её нет) — кнопка «Site settings» со значком ползунков (просьба владельца: «кнопка управления правами и данными сайта»). Она открывает карточку под собой (`App/SiteCard.cs`, по `SiteCard.swift` апстрима, без строк связи, печати, масштаба и звука):

- имя сайта без www;
- «Block Ads and Trackers». Пока блокирует uBlock Origin, выключить его на сайте можно только в его окне: «Open» закрывает карточку и открывает окно uBlock из его кнопки в полосе. Без uBlock — переключатель своего блокировщика: выключенный записывает сайт в `shield.paused` (тот же список, что в настройках), включённый убирает и запись сайта выше («example.com» для «www.example.com», `Shield.Resume`); страница перезагружается, как в апстриме;
- «Site Permissions»: Camera, Microphone, Location, Notifications, у каждого «Ask», «Allow», «Refuse», как в апстриме. Выбор хранит движок в профиле по источнику (схема, хост, порт): `SetPermissionStateAsync`, «Ask» стирает выбор (`Default`), и при следующем запросе движок спросит сам. Карточка читает выбор из движка (`GetNonDefaultPermissionSettingsAsync`) — в том числе тот, что человек сделал в вопросе самого движка;
- «Cookies and site data» — «Clear»: стирает куки, которые уходят на эту страницу (и сайта выше, по ним сайт узнаёт человека), и всё хранилище источника — куки на других путях, localStorage, IndexedDB, кэш, service worker (отладочный протокол `Storage.clearDataForOrigin`: у WebView2 стирание только всего профиля). Страница перезагружается. Разрешения не трогаются. В апстриме стирания по сайту нет.

Проверено в тихом окне (`check-site.ps1`, 16 из 16): кнопки нет на пустой вкладке и своей странице и есть на странице сайта; четыре разрешения «Ask»; «Allow», «Refuse» и «Ask» доходят до движка (страница видит `granted`, `denied`, `prompt`) и читаются обратно при новом открытии; «Clear» стёр обе куки (одну на другом пути) и localStorage, разрешения остались; с uBlock «Open» открывает его окно; при выключенном блокировщике строки блокировщика нет; снимки site-card, site-cleared. Переключатель своего блокировщика в окне не проверен: uBlock включается вместе с блокировщиком, и без него окно не запустить; правило «сайт выше» проверено в ядре.

## Колонка

Пустая вкладка («New tab») в окне одна: Ctrl+T и строка «+ New tab», когда пустая уже есть, ведут в неё и открывают поле, а не добавляют ещё одну (`Tabs.Open`, как `newTab` в апстриме).

Ctrl+S или первая кнопка в полосе убирают колонку: страница занимает всё окно. Сложенная колонка выезжает поверх страницы, если подвести указатель к левому краю окна, и уходит, когда указатель её покидает. Ctrl+S при выехавшей колонке оставляет её рядом со страницей. Состояние запоминается (`sidebar.folded`). Если в Windows выключены эффекты анимации, колонка появляется без движения.

Режим фокуса (Ctrl+Shift+F или «Focus mode» в настройках, `window.focus`, просьба владельца; в апстриме такого нет) оставляет только страницу: прячутся колонка, полоса с адресной строкой и системные кнопки окна (`App/Focus.cs`). Колонка выезжает от левого края, как сложенная, полоса — от верхнего, поверх страницы, и держится, пока указатель над ней или над кнопками окна (их рисует система, поэтому где указатель, окно спрашивает само раз в 350 мс). Пока полоса спрятана, за верх страницы окно не таскается. Это отдельный режим, Ctrl+S его не включает и не выключает; состояние запоминается. Проверено в тихом окне (`check-focusmode.ps1`, 13 из 13): Ctrl+Shift+F из страницы, страница во всё окно, места перетаскивания и кнопки окна спрятаны и возвращаются, выехавшая полоса и колонка, перезапуск в режиме, переключатель в настройках; снимки. Настоящей мышью у края не проверено: выезд вызывался тест-каналом.

Видео во весь экран (страница вызвала `requestFullscreen`, например кнопка YouTube) ставит окно во весь экран. Остаётся только страница: прячутся колонка и полоса, у карточки нет отступов, углов и края, края окна колонку и полосу не зовут. Окно узнаёт об этом из `ContainsFullScreenElementChanged` живой вкладки (`MainWindow.Immerse`). Выход — Esc или кнопка страницы; уход на другую вкладку тоже выводит страницу из полного экрана, как в Chrome. Развёрнутое окно возвращается развёрнутым (прежний presenter), режим фокуса и сложенная колонка — какими были. В апстриме страницу во весь экран показывает WebKit своим окном. Проверено в тихом окне (`check29.ps1`, 12 из 12): вход по настоящему нажатию, страница во всю ширину окна, полоса и колонка спрятаны, выход страницы, переход на другую вкладку, режим фокуса до и после. Тихое окно само во весь экран не встаёт: оно закрыло бы экран человеку. Поэтому сам полный экран окна и выход по Esc проверяются настоящим окном.

Кнопки полосы, строки вкладок и строки «New tab», «History», «Bookmarks», «Settings» — настоящие кнопки под нашим рисунком (`Ui.Bare`). Tab обходит их по порядку, вокруг той, где фокус, рисуется рамка, Enter и пробел нажимают, Delete на строке вкладки закрывает её, и фокус переходит на соседнюю строку — и когда закрыта живая вкладка: страница соседки, просыпаясь, фокус у колонки не забирает (`MainWindow.Drop`, `Tabs.Wake`). Enter на строке переключает вкладку и отдаёт фокус её странице. У своей страницы фокус получает её первый элемент (`Tabs.Face`): у истории и закладок это поле поиска, как в апстриме, у настроек — список разделов. Раньше при переходе от одной своей страницы к другой фокус спрятанной страницы падал на кнопку колонки с рамкой. У пустой страницы загрузок взять фокус нечему, и он по-прежнему уходит в колонку. При запуске фокус встаёт так же: у пустой вкладки — в поле адреса, у сайта — в страницу, у своей страницы — на её первый элемент. Раньше он ставился, пока окна ещё не было, не брался, и его забирала первая кнопка полосы («Hide sidebar») с рамкой; страница сайта после запуска оставалась без фокуса, пока по ней не щёлкнут. Теперь фокус ставится заново, когда окно встало (`root.Loaded`). Проверено в тихом окне (`check31.ps1`, 4 из 4). Проверено в тихом окне (`check18.ps1`, 9 из 9): переходы между историей, настройками и закладками, Delete на строке, когда соседка — своя страница, проснувшаяся и спящая. Экранный диктор читает имена: «Hide sidebar» или «Show sidebar», «Back», «Forward», «Reload», заголовок вкладки (как «tab», а не «button»). Кнопка, которой нечего делать (назад некуда), выключена: фокус её пропускает, диктор читает её недоступной. Щелчок мышью фокус не забирает: он остаётся на странице. Строки не вынимаются из колонки, пока стоят на своём месте, иначе фокус терялся бы при каждой перемене во вкладках (`MainWindow.Sync`).

Ссылка, открытая в новой вкладке, встаёт рядом со своей страницей, как `placeForLink` апстрима, а не в конец колонки. Средняя кнопка и Ctrl+щелчок открывают её за спиной: страница остаётся перед глазами, а несколько ссылок подряд встают по порядку. С Shift, как и ссылка с `target="_blank"`, вкладка открывается перед глазами. Переход на другую вкладку ряд заканчивает. Из приватной ссылка открывается приватной вкладкой, с теми же входами. В событии `NewWindowRequested` движок не говорит, чем открыли ссылку. Поэтому об этом заранее, на нажатии кнопки мыши, сообщает скрипт страницы тем же подписанным каналом, что и сочетания (`PageKeys.Clicked`, 3 проверки). Окно, которое страница открывает без нажатия, по-прежнему не открывается. Проверено в тихом окне (`check33.ps1`, 8 из 8; нажатия — настоящие, через отладочный протокол).

Ctrl+Shift+T («Reopen Closed Tab», `file.reopen`) возвращает закрытую вкладку на её место в колонке, перед глаза, как `reopen` и `ghosts` апстрима. Вкладки возвращаются по одной, последняя закрытая первой, на двенадцать шагов назад. Список живёт только в этом сеансе. Пустая и приватная вкладки не запоминаются. Своя страница возвращается тем же путём, что по её сочетанию: она в окне одна. Закреплённую Ctrl+W не закрывает, поэтому её возвращать не нужно. Отличие от апстрима: вкладка загружает адрес заново, без истории «назад» и места прокрутки (`ponytail:` в `Tabs.Reopen`). Проверено в тихом окне (`check28.ps1`, 8 из 8; Ctrl+Shift+T — нажатием в странице через отладочный протокол).

Закреплённые вкладки, как в апстриме (`Pins.swift`, `Browser.pin`), — базово: правый щелчок по вкладке (или клавиша меню) — «Pin Tab» и «Unpin Tab». Закреплённая встаёт в начало колонки за прежними закреплёнными, под ними черта; буква — первая буква сайта (`Pin`), дом — адрес, где закрепили (`Home`); оба поля в сессии те же, что на Mac. Крестика у неё нет: Ctrl+W, Delete и средняя кнопка её не закрывают, а кладут — страница отдаётся, место остаётся, а мы возвращаемся на прежнюю вкладку. Закреплённые не спят. Пустую вкладку и свои страницы не закрепляют. Отличия от апстрима: строки, а не квадраты; нет смены буквы, имени, возврата домой двойным щелчком, перетаскивания и общих для всех окон закреплённых (`pins.json`). Проверено в тихом окне (`check-pins.ps1`, 9 из 9).

Приватная вкладка (shy апстрима, `Browser.newShyTab`) — Ctrl+Shift+N, «New Private Tab» в сочетаниях. Пустая приватная, как и обычная, одна. У каждой приватной свой профиль движка в памяти (`IsInPrivateModeEnabled`, имя профиля по вкладке): свои куки и входы, у двух приватных — тоже разные. Она не пишет историю и значки сайтов на диск, не попадает в сессию, не спит (с последним движком профиль пропал бы) и не закрепляется. uBlock живёт в общем профиле, поэтому в приватной работает свой список блокировщика (`Shield.Blocks` и `Shield.Script` с `alone`). В колонке у неё справа тихий знак — перечёркнутый глаз, как eye.slash в апстриме. Ссылка из приватной в новую вкладку открывается приватной с тем же профилем — входы те же. Отличие от апстрима: расширений в приватных нет вовсе (в апстриме — по переключателю у расширения). Папку профиля движок заводит и для InPrivate — без адресов и куки (проверено поиском), но по одной на вкладку; поэтому профиль стирается (`CoreWebView2Profile.Delete`), когда закрыт его последний движок и когда закрывается окно, а саму папку движок убирает к следующему запуску. Проверено в тихом окне (`check-private.ps1`, 15 из 15).

## Полоса прокрутки и служебные страницы

Полоса прокрутки страницы — тонкий ползунок поверх содержимого: появляется при прокрутке и не отнимает у страницы ширину. Это флаг движка `OverlayScrollbar`, приложение ставит его само.

В поле адреса набираются `edge://` и `chrome://`: `edge://flags` открывает страницу экспериментов движка, `edge://gpu` — сведения о графике. Применяются ли выставленные там флаги после перезапуска, не проверено.

## Блокировщик

Блокирует uBlock Origin 1.76.6 — полный, MV2, как опубликован (решение владельца). Он лежит в установке, в `Extensions\uBlock0.chromium` рядом с `aerio.exe`, с текстом лицензии GPLv3 и запиской `Extensions\uBlock Origin.txt` (откуда взят, контрольная сумма, где исходники). При первом запуске он встаёт в профиль движка (`App/UBlock.cs`), дальше движок поднимает его сам. Переключатель «Block ads and trackers» на странице настроек включает и выключает uBlock; строка «uBlock Origin» → «Open» открывает его панель во вкладке: списки фильтров, доверенные сайты, свои правила. Свой список ниже при работающем uBlock молчит (`Shield.Delegated`); если uBlock не нашёлся или движок его не принял, блокирует свой список.

Проверено в тихом окне (`check-ublock.ps1`, `check-ublock2.ps1` в черновиках): в ролике YouTube без uBlock в ответе плеера есть рекламная вставка (`adPlacements` 1), с ним — нет (0); Google Analytics на местной странице остановлен; выключенный переключатель выключает uBlock, и реклама в ролике возвращается, а свой список не включается; после перезапуска uBlock один. Предел: только что поставленный uBlock несколько секунд разбирает свои списки, и первая страница самого первого запуска проходит без него. Всплывающего окна uBlock (выключить на этом сайте одним нажатием) нет: у WebView2 нет точек входа для расширений; доверенный сайт добавляется в его панели.

Свой список — то, что блокировало до uBlock. Чужие запросы к доменам из списка останавливаются, рекламные места прячутся до разбора страницы. Запросы сайта к самому себе и переходы самой вкладки (по ссылке, по адресу, через перенаправление) не трогаются.

У WebView2 нет списка правил, как у WebKit, есть только событие «запрошен ресурс». Движку отдаются фильтры по доменам из списка, поэтому в оболочку приходят только запросы к ним, а остальные идут без задержки. Для списков в тысячи правил этот путь не годится: понадобится расширение с declarativeNetRequest.

Список: 44 домена из апстрима и российские сети со счётчиками, которых в апстриме нет. Российская часть составлена по обходу двенадцати крупных сайтов 20.11.2026. Рекламный код Яндекса и метка ретаргетинга VK стоят на общих доменах, поэтому для них правила с путём (`yandex.ru/ads/`, `vk.ru/rtrg`): карты, вход и виджеты с тех же доменов проходят. На тех же двенадцати сайтах со старым списком останавливалось 11 запросов, с новым 110; объём текста и число картинок при этом почти не меняются.

Окно, которое страница открывает сама, без нажатия человека, не открывается: так приходит всплывающая реклама.

Правила для YouTube не перенесены. На части сайтов от баннера остаётся пустая рамка: её рисует сам сайт. Выключатель и список сайтов, на которых блокировщик выключен, — на странице настроек; выключить его прямо с вкладки сайта пока нельзя. Влияние на скорость загрузки не измерено.

Сочетания по умолчанию: Ctrl+T, Ctrl+Shift+N, Ctrl+Shift+T, Ctrl+L, Ctrl+W, Ctrl+S, Ctrl+Shift+F, Ctrl+Shift+B, Ctrl+H, Ctrl+запятая, Ctrl+R и F5, Alt+←/→, Ctrl+Tab и Ctrl+Shift+Tab, Ctrl+P, Ctrl+Shift+I и F12, Ctrl+J.

Их можно сменить: Settings › Keyboard Shortcuts (перенос `ShortcutsPage.swift`). Восемнадцать команд окна, у каждой кнопка с её сочетанием: нажать и набрать новое. Сочетание, занятое другой командой, переходит со второго нажатия («Used by … — press again»), Esc оставляет как было, Backspace или Delete снимают; в меню по правой кнопке — «Clear Shortcut» и «Reset to Default»; «Reset All» внизу появляется, когда что-то сменено. Не годятся клавиша без Ctrl и Alt (кроме F1–F12) и то, что принадлежит Windows и полю ввода: Esc, Tab без Ctrl, Ctrl+Alt (так приходит AltGr), F10, Alt+F4, Ctrl+C/V/X/A/Z/Y, Ctrl со стрелками, Home, End, Backspace, Delete. F5 и F12 закреплены за перезагрузкой и DevTools. Хранится только отличие от умолчания — настройка `shortcuts` (ключ апстрима), список `id=сочетание` (`Core/Shortcuts.cs`). Новое сочетание открытая страница ловит со следующей загрузки. Пока кнопка ждёт сочетание, сочетания окна молчат. Сочетания в описаниях строк настроек («Ctrl+S» у складывания) берутся, когда страница настроек строится.

Они работают и когда фокус в странице. Нажатия в странице забирает движок, и до сочетаний окна они не доходят, поэтому в каждую страницу и её рамки первого уровня ставится скрипт (`Core/PageKeys.cs`): он ловит нынешние сочетания команд из таблицы (по умолчанию Ctrl+T, Ctrl+Shift+N, Ctrl+Shift+T, Ctrl+W, Ctrl+L, Ctrl+S, Ctrl+Shift+F, Ctrl+Shift+B, Ctrl+H, Ctrl+запятая, Ctrl+Tab, Ctrl+Shift+Tab) и сообщает о них окну. Команды, которые движок в странице делает сам (печать, перезагрузка, назад и вперёд, DevTools, загрузки), скрипт ловит, только когда их сочетание сменено; прежнее сочетание движок в странице по-прежнему понимает сам. Клавиша берётся по виртуальной клавише, поэтому при русской раскладке всё то же. Как в Chrome, Ctrl+T, Ctrl+Shift+N, Ctrl+Shift+T, Ctrl+W, Ctrl+Tab и Ctrl+Shift+Tab страница не получает вовсе, а остальные может забрать себе: если редактор сам обработал Ctrl+S, колонка не складывается. Сама страница действие окна вызвать не может: скрипт берёт только настоящие нажатия, а сообщение подписано меткой сеанса, которой страница не видит. Ctrl+W движок может обработать и сам и тогда просит закрыть окно (`WindowCloseRequested`): вкладка закрывается. Так же закрывается вкладка, чья страница вызвала `window.close()` там, где Chrome это разрешает (вкладка с одной записью в истории). Ctrl+R, F5, Alt+стрелки, Ctrl+P, F12 и Ctrl+J движок в странице понимает и сам. На страницах движка (`edge://`, PDF, страница ошибки) и в рамках глубже первого уровня скрипта нет: там работают только сочетания движка.

Функции движка из оболочки: Ctrl+P — диалог печати браузера, F12 и Ctrl+Shift+I — DevTools. Внутри страницы эти клавиши движок понимает сам; оболочка повторяет их, чтобы они работали и из поля адреса, и из колонки (`Tabs.Print`, `Inspect`). Действуют на живую вкладку; у своей страницы и у спящей вкладки движка нет, там они ничего не делают. Масштаб (Ctrl+плюс, минус, 0) и поиск по странице (Ctrl+F) работают только при фокусе в странице: масштаб задаётся через контроллер движка, а элемент WinUI его не отдаёт.

Загрузки ведёт движок, а список — свой (`App/DownloadsPage.cs`, как `DownloadsPanel` и `Fetching.swift` апстрима): страница `browser://downloads`. Её открывают Ctrl+J, адрес и кнопка со стрелкой в полосе; кнопка видна, пока файлы идут. Окошко движка не показывается (`DownloadStarting.Handled`). Если Ctrl+J в странице поймает сам движок, его окошко закрывается и открывается страница; этот путь не проверен: тест-канал не шлёт сочетания с Ctrl. На странице две группы. «Current downloads»: имя, сайт, сколько пришло из скольких, кнопки Pause/Resume и Cancel; у сорвавшейся загрузки, которую не продолжить, вместо Cancel — Remove. «Completed»: имя, сайт и время, кнопки Open (программой, назначенной в Windows), Show in Folder (Проводник с выделенным файлом) и крестик «забыть». Внизу — Clear List. Список хранится в `downloads.json` (`Core/Downloads.cs`, ключи `Keep` апстрима): новые первыми, не больше пятидесяти. Убрать строку или очистить список — файлы остаются на месте. Стёртый файл остаётся строкой с пометкой «Deleted». Адрес файла из приватной вкладки не записывается. Файл падает в папку загрузок Windows; если имя занято, движок дописывает «(1)». Вкладка, с которой начали скачивание, остаётся на своей странице. Вкладка с идущей или приостановленной загрузкой не спит. У закрытой вкладки движок остаётся скрытым, пока её файлы не дойдут. Без этого файл движок докачал бы сам, но события о нём уже не приходили бы, и строка замерла бы. Вкладка, открытая только ради файла, становится пустой («New tab»). Файл, открытый в новой вкладке, запрашивается у сайта дважды. Второй запрос — повтор оборванного первого перехода (см. «Окно»), и его загрузка отменяется до первых байтов. Адрес файла не попадает ни в историю, ни в сессию, поэтому после перезапуска ничего не скачивается заново (`Tabs.Wake`, конец несостоявшегося перехода). Вопроса «куда сохранить» и выбора папки нет; при выходе идущие файлы обрываются без вопроса. Проверено в тихом окне на своём медленном сервере (25 проверок, 0 провалов): быстрый и медленный файл, пауза, продолжение, отмена, кнопка в полосе, вкладка не спит, вкладку закрыли до конца загрузки, приватная, Forget, перезапуск, стёртый файл, Clear List. В тестовом мире файлы ложатся в его папку `Downloads`.

## Расширения

Все вкладки работают в одной среде движка, и в ней включены расширения Chrome (`AreBrowserExtensionsEnabled`, `Tabs.Shared`). uBlock Origin ставится сам (см. «Блокировщик»).

Свои расширения — в настройках, раздел «Extensions» (как Settings › Extensions в апстриме, `App/Addons.cs`, `Core/Extensions.cs`). «Load an unpacked extension» → «Choose…»: папка с `manifest.json`. Движок читает распакованную папку всё время, пока расширение стоит, поэтому ему отдаётся копия в папке данных (`Extensions\<имя папки>`), а не папка человека; `Extensions\installed.json` хранит id от движка, версию, страницу настроек из манифеста и откуда взято. Под ней — по строке на расширение: имя, «Version … · From “папка”», переключатель и меню «…» с «Options» (страница настроек во вкладке) и «Remove» (убирает у движка, стирает копию и запись). Ошибка движка — красной строкой под «Load an unpacked extension». uBlock и встроенные расширения движка в этом списке не показываются. Когда ни одна страница не проснулась (открыты только настройки), список и дела идут через невидимый движок на время дела (`Tabs.WithProfile`, тот же, что у очистки куки). Проверено в тихом окне (`check-addons.ps1`, 14 из 14): установка из папки, строка в настройках, выключенное невидимым движком выключено и у живого, «Options», после перезапуска на месте, «Remove». Сам диалог выбора папки в тихом окне не открывали: он забрал бы фокус у человека.

Из Chrome Web Store — первая строка раздела: ссылка на страницу расширения или его id и «Add» (Enter), рядом «Open the Store». Как в апстриме (`Crx.swift` → `Core/Crx.cs`): .crx берётся с открытого адреса обновлений (`clients2.google.com/service/update2/crx`), aerio представляется той версией Chromium, что стоит на самом деле. Заголовок CRX3 проверяется: id — первые 16 байт SHA-256 открытого ключа буквами a–p, и подпись этим ключом (RSA, PKCS#1 v1.5, SHA-256) должна сходиться над zip; иначе отказ. zip распаковывается в `Extensions\<id магазина>` (записи с путём наружу не пишутся), дальше как с папкой; в строке — «Chrome Web Store». То же расширение второй раз не ставится. Магазин узнаёт, какое расширение добавляют, — как и от Chrome. Проверено: ядро — на своих .crx, подписанных ключом, созданным в проверке (чужой ключ, чужой id, изменённый zip, CRX2, обрезанный файл не проходят); в тихом окне (`check-store.ps1`) — настоящий JSON Formatter 0.10.2 из магазина ставится за секунду, включён у движка, второй раз не ставится, «Remove» убирает распакованное; не ссылка — красная строка «That isn't a Chrome Web Store link or extension id». Id у движка свой (по пути папки), не id магазина.

Кнопки расширений — в правом конце полосы окна, перед кнопками окна (`App/Actions.cs`, как `ExtensionButtons` и `ExtensionPopup.swift` апстрима). Кнопка есть у каждого включённого расширения, у которого в манифесте `action` или `browser_action`, и у uBlock; значок — из манифеста (`default_icon`, иначе `icons`; наименьший не меньше 32 пикселей, `Extensions.Button` в Core), без значка — первая буква имени; имя для диктора — `default_title`. Нажатие открывает `default_popup` во всплывающем окне под кнопкой (`Flyout` со своим движком в общей среде): окно одно, второе нажатие на ту же кнопку или щелчок мимо его закрывают, `window.close()` страницы тоже; ссылка из окна открывается во вкладке. Размер — по странице, от 25×25 до 800×600: ширина по содержимому без переносов, высота при ней; меряется после загрузки и ещё через 0,25 и 1 с, до первого замера окно невидимо. Выключили расширение или блокировщик — кнопка пропадает.

Для расширения каждый WebView2 — своё окно с одной вкладкой (проверено), поэтому страница окна, спросив `chrome.tabs.query({active: true, currentWindow: true})`, нашла бы саму себя. Перед загрузкой в неё встаёт скрипт (через отладочный протокол: `Page.addScriptToEvaluateOnNewDocument` при включённом `Page` — обычный скрипт хоста до страниц расширений не доходит): запросы с `currentWindow` или `lastFocusedWindow` уходят к окну живой вкладки, номер которого даёт `Browser.getWindowForTarget`. Фоновая страница расширения (так спрашивает uBlock) ищет «текущую вкладку в последнем окне с фокусом»: поэтому фокус окно получает только после первого замера, а до того его держит страница сайта. Проверено (`check-actions.ps1`, 12 из 12): своё расширение получает кнопку, окно 240×120 по странице, из окна «текущая вкладка» — страница сайта, uBlock показывает её сайт, второе нажатие и щелчок мимо закрывают, кнопка uBlock уходит и возвращается с блокировщиком.

Чего у кнопок нет: значка, который расширение ставит себе само (`chrome.action.setIcon`), счётчика (`setBadgeText`), нажатия у кнопки без окна (`chrome.action.onClicked`) — WebView2 ничего из этого наружу не отдаёт; закрепления и списка под пазлом, как в апстриме. Подменён только `chrome.tabs.query`: `tabs.getCurrent` и `windows.getCurrent` отвечают про само окно.

На странице расширения в магазине внизу страницы — плашка «Add this extension to aerio» с кнопкой «Add» (`App/StoreOffer.cs`, `StoreOffer` апстрима): кнопка самого магазина там говорит «Switch to Chrome». Какое расширение — только из адреса вкладки (`Crx.StoreId`: https, сам магазин, id из пути `/detail/`), не из того, что говорит страница; нажимает «Add» только человек. Ставится тем же путём, что из настроек; пока ставится — «Adding…», ошибка — красным на плашке; поставленному плашка не предлагается. Проверено на настоящем магазине (`check-offer.ps1`, 8 из 8). Серая кнопка магазина и баннер «Switch to Chrome» остаются как есть: подмены кнопки в самой странице (`StoreRelay.swift` апстрима) нет.

Пока нет: «Reload» (та же папка второй раз встаёт вторым расширением), обновлений расширений из магазина, значков расширений в строках.

Проверено своими расширениями (`check-extensions.ps1` в черновиках): скрипт расширения выполняется в странице; правило MV3 `declarativeNetRequest` и MV2 `webRequestBlocking` останавливают запрос (без расширений тот же скрипт грузится); страница настроек расширения (`chrome-extension://…/options.html`) открывается во вкладке; после перезапуска расширения на месте. Своих кнопок и всплывающих окон расширений у WebView2 нет (см. выше). Встроенные расширения движка — «Microsoft Clipboard Extension» и «Microsoft Edge PDF Viewer».

## Тест-канал

Работает только в тестовом мире. Именованный канал `\\.\pipe\<папка хранилища>.bench`, строка JSON туда, строка обратно: `{"do": "tabs"}`.

Команды: `tabs` (у вкладки ещё `pin`, `private` и `failure` — почему не состоялся последний переход: `WebErrorStatus` и адрес движка), `open` (`url`, `behind`), `new`, `private` (как Ctrl+Shift+N), `go` (`text`), `select` и `close` (`id`), `wait` (`id`: пока вкладка не догрузится), `js` (`id`, `code`: выполнить на странице и вернуть результат), `field` (`text`), `type` (`text`), `theme` (`look`: `light`, `dark`, `system`), `shield` (`on`), `fold` (`on`), `hover` (`on`: указатель над адресной строкой и его уход), `reveal` (`on`), `crown` (`on`: полоса выезжает в режиме фокуса, как от указателя у верхнего края), `cdp` (`id`, `method`, `params`: команда отладочного протокола движка, например настоящее колесо мыши или нажатие клавиши в странице; если команда закрыла саму вкладку, через 5 с отвечает `unanswered`), `print` (как Ctrl+P), `downloads` (как Ctrl+J; отвечает `active` — идущие загрузки, и `kept` — список скачанного), `bookmarks` (открыть страницу закладок; отвечает `sites` — все сайты по порядку: `title`, `url`, `path` — папки через «/»), `keys` (сочетания, которые окно зарегистрировало: Ctrl в тихое окно не послать), `extension` (`path`: поставить распакованное расширение из папки тем же путём, что «Choose…» в настройках), `extensions` (поставленные расширения), `probe`.

Для своих страниц: `settings` и `history` (открыть страницу), `set` (`key`, `value`: записать настройку), `visit` (`url`, `title`, `ago`: место в истории, как если бы там были столько часов назад), `sheet` (элементы страницы с именами и состоянием, `enabled` — доступен ли), `press` (`name`: нажать элемент), `fill` (`name`, `text`: набрать в поле), `focus` (`name`: фокус с клавиатуры), `step` (`way`: `next` и `previous` — куда уйдёт фокус по Tab и Shift+Tab, `up`, `down`, `left`, `right` — по стрелкам, `none` — где он сейчас), `dismiss` (закрыть открытое меню и окно расширения), `actions` (кнопки расширений в полосе: `id`, `name`), `act` (`id`: нажать кнопку расширения), `popup` (открытое окно расширения: `url`, размер; с `code` — ответ выражения в нём, обещание дожидается), `choose` (на странице истории: `name` — Ctrl+щелчок по строке, с `shift` — Shift+щелчок, `all` — Ctrl+A, `none` — Esc; отдаёт, сколько выбрано: настоящий Ctrl тихому окну не послать). `press` нажимает элемент тем же путём, что экранный диктор, поэтому заодно проверяет, что элемент ему виден.

Для полосы и колонки: `chrome` — их названные элементы в том же виде, что у `sheet` (кнопка сайта и адресная строка, кнопки полосы, строки вкладок, «New tab», «History», «Bookmarks», «Settings», кнопки расширений, в конце — открытые окошки полосы, например карточка сайта; сложенная колонка и спрятанная в режиме фокуса строка не считаются). `press`, `focus` и `fill` ищут имя сначала на своей странице, потом здесь; `menu` (`name`) открывает меню элемента, как правый щелчок (у строки вкладки — «Pin Tab»), его строки жмёт `press`, закрывает `dismiss`. Пустая вкладка зовётся «New tab», как и строка под вкладками: первой найдётся вкладка. `step` с `none`, когда фокуса нет ни на чём, сам ставит его на первый элемент. Указатель человека над тестовым окном «наводит» строки под собой и портит снимки: проверку в таком случае повторяют. `probe` отдаёт и места полосы, где нажатие своё, а не перетаскивание окна (`holes`: x, y, ширина, высота в точках экрана), и ширину окна (`width`): `WM_NCHITTEST` окна о них не говорит — отвечает «заголовок» и над кнопками. Ещё `caption` — где окно таскают, `buttons` — видны ли кнопки окна, `focused` и `crowned` — режим фокуса и выехавшая полоса, `immersed` — страница во весь экран, `at` — где фокус с клавиатуры (имя элемента, вид, `FocusState` через « | »). Перетаскивание всей полосы ставит `Passthrough` после каждой раскладки: после режима фокуса `SetTitleBar` его сам не возвращает, остаётся системный заголовок в 32 точки до кнопок.

С переменной `BROWSER_QUIET` окно не становится активным и не встаёт поверх других. Так запускаются проверки скриптом, пока за компьютером работает человек: иначе его нажатия попадают в проверяемый браузер.

Канал, а не Unix-сокет, потому что у Python на Windows нет `AF_UNIX`. Клиент открывает канал как файл, читает до перевода строки и закрывает; если канал занят, повторяет. Клиент на Python — `Windows/bench.py` (переделка `./bench` апстрима): `python Windows/bench.py start`, затем `python Windows/bench.py tabs` или `open url=…` (`ключ=значение`, значение — JSON или строка; можно и строкой JSON целиком), `stop` закрывает окно штатно (WM_CLOSE: сессия и рамка окна записываются), `reset` ещё и стирает мир. Мир — `BENCH_WORLD`, по умолчанию `shell`, как у `drive.ps1`. Как модуль — `bench.start()`, `bench.ask({...})`, `bench.stop()`: так начинают переносить тесты апстрима из `Tests/`. Первый запуск сразу после сборки бывает дольше 20 с, `start` ждёт до минуты. Проверено (`check_bench.py`, 11 из 11): сброс, запуск без фокуса, `js` с кириллицей, ошибка команды, 20 запросов подряд, штатное закрытие.

## Отличия от macOS

- **Кнопки окна системные и справа**, а не «светофор» слева. Полоса сверху ниже: 48 вместо 52 — высота высокой системной полосы (`TitleBarHeightOption.Tall`), так кнопки окна и всё остальное в полосе стоят на одной средней линии. Система рисует кнопки окна от самого верха окна, а наша полоса начинается под его краем в один пиксель, поэтому кнопки, адресная строка и кнопки расширений подняты на этот пиксель (`Passthrough`). На снимке значки полосы и кнопки окна сходятся до полпикселя (разная высота значков).
- **Шрифт и значки свои**: Segoe UI Variable и значки Lucide (лицензия ISC). San Francisco и SF Symbols лицензия Apple разрешает только на её платформах. Значки рисуются вектором: контуры Lucide лежат строками в `Design.cs`, `Ui.Glyph` делает из строки `Path` со штрихом кистью из `Palette` и скруглёнными концами. Пакета и файла шрифта нет, от версии Windows вид не зависит. Толщина штриха задаётся в единицах сетки набора (2 — как в Lucide; мелким крестику и стрелке списка — 2.5). Новый значок: взять `d` из его файла на lucide.dev, склеить контуры в одну строку, начало каждого «m x y …» записать как «M x y l …», `rect` и `circle` переписать контуром.
- **Адреса нормализуются.** `System.Uri` приводит хост к нижнему регистру, убирает порт по умолчанию и лишнее процентное кодирование. Регистр пути и запроса различается, как в апстриме.
- **Формат файлов общий с Mac**: `history.json` и `session.json` оттуда читаются как есть.

## Чего пока нет

- В колонке с клавиатуры: стрелки между строками не ходят (только Tab; в апстриме их тоже нет), а какая вкладка живая, диктор не слышит (её имя — в заголовке окна). Крестик вкладки виден только под указателем; с клавиатуры вкладку закрывают Delete на строке и Ctrl+W.
- «Выключить блокировщик на этом сайте» прямо с вкладки; широких списков правил.
- Папок для закладок, их переименования, панели закладок и импорта (см. «Закладки»).
- Анимаций, кроме движения колонки.
- Групп, сплитов и пространств.

## Имя

Значок вшит в `aerio.exe` и лежит рядом с программой: окно берёт его для заголовка и панели задач.
